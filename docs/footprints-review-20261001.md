# 足迹模块：场馆旅程与产品评审

核对日期：2026-10-01。用户要求：城市光点先靠近真实场馆地图，点击场馆再进入夕阳外景；不同场馆拥有对应场景；删除外景／夜场加减按钮；丰富演出资料，并评价模块。

## 当前判断

足迹现在具有清楚的浏览路径和可辨识的视觉表达，适合在比赛 Demo 中展示“找一场现场 → 走进场馆 → 收藏作品 → 留下自己的记忆”。它还不能承担完整、持续更新的追星日程服务。继续增加特效的收益已经低于补齐数据可信度、真实现场歌单和个人回访理由。

它与《歌里有我》主轴的联系，应当落在同一场次里保存的个人记忆：人生日期 × 场次 × 音乐位置。仅有巡演地图和漂亮场景，难以证明真实使用价值或与现有票务／歌单产品的差异。建议比赛演示以一位听众的完整记录与回访为主，地图运镜作为进入这段经历的入口。

## 本轮补充（2026-10-01）

星群已从规则排列改为按场次稳定生成的错落位置，大小和闪烁节奏变化，长歌名留出间距；小屏可轻滑浏览，不因选曲或歌单高度变化打乱位置。现场图见[星群实录](footprints-starfield-20261001.jpg)。原表中关于规则排列的视觉问题已处理，长歌单在实体手机上的使用效果仍需观察。

新增[本地资料维护工具与说明](footprints-data-maintenance.md)，支持变更预览、证据元数据校验、按旧版本写入和审核记录。它提供后续采集／AI提取共用的校验入口，尚未开启持续自动更新，当前84条记录与未确认歌单状态不变。个人到场记忆的跨模块调整按用户本轮要求暂缓。

## 仍需优先优化

| 优先级 | 问题 | 下一步与验证方法 |
|---|---|---|
| 1 | 日程完整性与新鲜度仍不足；大量记录是历史场次，84 条不是全国覆盖。静态资料随着改期／取消会失效 | 建立按歌手维护的来源与更新任务，保存变更记录和最后核验时间；区分未来／历史／取消，默认优先待演。以抽样官方公告检查日期、场馆、状态，衡量覆盖率与更新延迟 |
| 1 | 目前所有曲目都属于关联作品，不能保证某晚确实演过；歌手音源缺失 | 获取可用播放接口／音频，再补有证据的现场歌单与版本；未确认曲目继续明确说明。验证歌曲名、版本、现场次序和点击播放，不用原创样例代替歌手录音 |
| 2 | 浏览场馆有吸引力，但看过一次以后为什么回来尚不充分 | 把“我去过／我想去”、个人照片、一句话和音乐位置沉淀在同一场次；从我的记忆直接重返这一晚。先观察用户是否主动记录、隔天回访及再次找回，而非用动画点击量判断价值 |
| 2 | 演出数据与场景可能造成过度真实的印象 | 保留简短“场景示意”；按官方建筑参考修正明显结构差异。封闭场馆保留屋顶，星星作为选曲交互浮在上方，不能把天花板解释成真实可见星空 |
| 2 | 曲目超过八首时星空入口变成可滚动排列，视觉记忆点弱；小屏空间有限 | 下一轮设计分段星群／章节切换，突出当前曲目和可继续浏览的提示，避免所有曲目挤满画面。用真实长歌单检查遮挡、触控命中和滚动发现性 |
| 3 | 景深图只是有限视角，多图仍增加资源体积；桌面验证无法代表手机性能 | 实体中端手机检查首次加载、持续拖动、纹理切换、后台恢复。依据测量加入清晰度分级、按场景延后加载；完整360°环绕需要多视角或真实模型，不能靠继续拉伸单图实现 |

## 数据与视觉边界

- 84 条日期中 3 条明确取消，其余 81 条未标取消并不等于实际举行。13 座城市有场次记录；47 座城市是地图选择范围。
- 18 条记录有来源支持的开演时间，其余 66 条明确为未知；未知时间不填通用19:30。最新收录日期到2026-10-05，不能承诺覆盖全部近期行程。
- 16 个场馆有带来源的 WGS84 坐标；部分坐标来自建筑范围中心，不是导航入口，也不是官方测绘成果。日期与地理依据见[目录来源核对](footprints-catalog-sources.md)。
- 新增图像为建筑参考概念渲染，不是场馆实拍或某一场演出的现场照片。舞台、灯海、周边景观存在演绎，拖动是受限景深视角。
- 收藏存入本项目账号，尚未同步到 QQ 音乐；未提供歌手音源，不能声称已经播放这些真实歌曲。
