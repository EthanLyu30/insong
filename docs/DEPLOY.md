# 公网部署

## 香港服务器配置

正式迁移目标为 `https://insong.me`。服务器是腾讯云香港轻量应用服务器，公网地址 `43.132.237.65`，Ubuntu 24.04，2核4GB/70GB。已购买的50GB优选流量包用于中国内地访问香港的线路。迁移验收结果以本文末尾记录为准。

| 部分 | 运行位置 |
| --- | --- |
| HTTPS、前端、同源 API 转发 | 香港服务器 Nginx |
| FastAPI、固定版本的量化 E5 | 非 root 单进程 Docker 容器 |
| 账号、登录会话、记录、收藏、处理后的照片 | 同机 PostgreSQL 持久卷，私有 insong schema |
| 域名注册与 DNS | Cloudflare |
| 自动检查和发布 | EthanLyu30/insong 的 GitHub Actions |

应用前端和 API 使用同一个域名。足迹底图仍读取 Esri、OpenFreeMap 和 Mapterhorn 的第三方瓦片及字体，地图首次加载速度也受这些外部资源影响。数据库和后端不开放独立公网端口；生产数据库连接保持 TLS verify-full。Cookie 使用 Secure、HttpOnly、SameSite=Lax，API 和私密照片保持 no-store。E5 查询在服务器处理，不调用外部模型 API。草稿仍留在当前浏览器，不随数据库迁移。

## 推送与自动发布

先推源仓库 `Saskia-1/TME:lxy`，再把同一提交推到 `EthanLyu30/insong:main`。原仓库 main 不参与部署。

```powershell
git push origin HEAD:lxy
git push deploy HEAD:main
```

只有个人仓库 main 的 push 可以发布。前端测试和构建、原生 PostgreSQL 后端测试、部署安全测试、真实 E5 与最大允许图片的受限容器检查都成功后，才通过专用 SSH 账户上传。重新构建的前端须与测试 job 的完整文件摘要一致；服务器再次核对提交 SHA、镜像标签和发布包内每个文件。

服务器预热另一份后端，确认健康与 E5 后切换 Nginx。进行中的请求排空前保留旧后端；下一次复用它时也检查请求是否结束。旧工作流重跑不能覆盖更新的发布序号，客户端也会核对最新 main SHA。部署锁由操作系统管理，进程结束后自动释放。

`HK_DEPLOY_ENABLED` 是个人仓库的生产发布开关，初次迁移完成后开启。SSH 私钥和固定主机公钥保存在个人仓库 Secrets；密钥不给普通 shell、数据库访问或 Docker 用户组权限，授权到服务器到期日结束。

两次 push 是独立操作，第一个成功不代表第二个成功。检查 Actions 全部成功，并核对线上响应头 `X-Insong-Release` 与 main 提交相同。Vercel 的旧入口跳转至正式域名，API 转发也指向香港服务；Render 的旧后端在迁移后暂停，Supabase 原始数据保留用于恢复。旧 Render 属于 Blueprint 管理，自动部署由仓库配置的 `autoDeployTrigger: off` 停用，停写变量保持1。[Render 配置说明](https://render.com/docs/blueprint-spec#autodeploytrigger)

## 运维与凭据

应用布局位于 `/opt/insong`：

- `secrets`：数据库连接与密码，仅管理账户可读取。
- `tls`：数据库内部 CA 与服务证书，应用只挂载公开 CA。
- `https`：网站证书，私钥仅管理账户可读取。
- `releases`：核对过的前端和镜像。
- `shared`：带内容指纹的脚本与字体，保留供旧页面继续加载。
- `state`：当前及上一版本、排空状态、部署锁。
- `backups`：受保护的数据库快照与验证回执。

保留当前、上一版本和一份额外版本。历史上传包和本项目镜像受控清理，运行中的镜像保持保留；不会执行全局 Docker prune。发布前为数据库预留至少5GiB空间，并检查候选解包和加载镜像所需余量。共享指纹资源的小文件继续保留，需关注长期增长。

网站证书采用 Let's Encrypt，切换后以 HTTP-01 自动续期。HTTP 仅用于转 HTTPS 和证书验证。服务器到期日是2026年11月7日；域名续费和服务器续费是独立的，不会因自动部署而延期。

## 数据迁移和恢复

正式迁移先对原后端设置 `MIGRATION_READ_ONLY=1`，确认写请求返回503和 Retry-After，再导出 Supabase 私有 insong schema。导出不包含本机 SQLite 或其他项目的数据。

恢复先在隔离数据库核对完整行摘要、外键和序列，包括会话哈希及照片字节。最终冻结快照验证后才启用新服务和切换 DNS。迁移不删除 Supabase 原始数据，也不会通过前端接入数据库凭据。

新版本异常时，优先以新的 main 提交恢复已验证代码；旧 CI 重跑故意不能直接回滚。代码回退不恢复已删除记录，不重建数据卷。数据库恢复前应保存现有数据，在新的隔离库恢复并验证，再安排停写切换，避免覆盖迁移后的新记录。

当前备份保存在同机私有目录，不能抵御整台服务器丢失。正式长期使用前，持有人应另存一份受保护的异地备份；原 Supabase 仅保存迁移之前的数据。

## 加载与排查

静态图片、字体和页面由香港服务器直接提供，后端不再依赖免费实例休眠唤醒。首页公开样例随前端显示，其他页面按需加载；个人内容验证登录后读取。脚本及字体使用指纹与 immutable 缓存，HTML 使用 no-cache，API 不缓存。

- 页面打不开：检查 DNS、TCP443规则、Nginx 和网站证书。
- 页面正常但数据失败：检查 `/api/health` 和后端容器状态。
- 数据库连接失败：核对内部 postgres 主机名、CA 挂载、私有运行配置；不要输出连接串。
- 登录或保存403：核对访问域名和允许来源，避免给私密响应套静态缓存。
- 发布失败：看 Actions 的检查结果和服务器候选状态；失败候选不会替换健康版本。排空超时会保留旧后端，须等请求结束后再发版。

香港优选流量改善线路，不保证每个运营商、地区和时段都相同。首访仍需下载图片和脚本，不能保证全部内容瞬间出现。

## 迁移验收

配置与代码检查：前端249项测试及构建，后端206项本地测试，部署安全65项测试通过。原生数据库 verify-full 正反例、Nginx HTTP/2、真实 E5 和20MP图片并发处理通过。实际候选失败后保留原版本、健康候选切换、旧指纹资源访问和跨 reload 慢上传均已验证。

源数据隔离恢复演练和正式停写快照的21项表和序列摘要一致。新服务器 HTTPS 下的账号、两张私密照片、公开与撤回、记录编辑、场次快照、关注、到场和 E5 匹配均通过；重启后会话、记录、照片字节与关注保留。验证样例已按归属清理，所有原始行摘要再次与冻结源库一致，序列不回退。
