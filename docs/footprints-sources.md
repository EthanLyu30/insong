## 曲目与个人歌单

每场目录支持 `setlist_kind: confirmed / partial / artist_collection`。目前全部为 `artist_collection`，代表歌手关联作品，未核实这些作品是否在本场演出，也没有已核实的完整本场歌单。按用户要求，夜空直接列曲目，不摆资料出处和外站跳转；不能在参赛演示中将这些作品说成现场实际完整歌单。未来有可核实场次歌单时，应记录来源并改为 `confirmed` 或 `partial`。

目录仍保留 QQ 音乐搜索 URL 作为数据兼容字段，但足迹页面不再展示外链。收藏由服务端根据场次目录生成曲名、艺人等快照，数据库按账号保存；同一账号同一场次重复收藏返回同一个歌单。历史收藏不随目录曲目变化而被重写。这是站内收藏，不是 QQ 音乐平台账号的歌单同步。

## 地图与场馆

- [DataV GeoAtlas](https://geo.datav.aliyun.com/) 的[全国省级 GeoJSON](https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json)作为本地打包的省界图层，保留原省级轮廓、台湾、香港、澳门及南海诸岛。卫星底图由 [Esri World Imagery](https://services.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer)在线提供，MapLibre WebGL 渲染；地图和三维影像视图保留署名。
- 城市经纬度为城市中心的近似点位，包含省会／首府及主要演出城市；点击城市展示目录内场馆。城市点位不是场馆地址。
- 场馆地址匹配使用 [ArcGIS World Geocoding Service](https://geocode.arcgis.com/arcgis/rest/services/World/GeocodeServer)。深圳大运、杭州奥体、天津奥体、南昌国际体育中心、上海体育场、广州宝能、五棵松、重庆奥体、济南体育馆共 9 个场馆接受匹配；三亚、赣州、厦门及济南体育场匹配不充分，保留城市定位并降低放大级别。坐标是地理编码结果，未经现场测量。
- Three.js 渲染场馆屋面、玻璃幕墙、看台、舞台、灯光及星空；三维建筑是原创通用模型，不承诺真实场馆建筑外形。地面采用对应场馆坐标附近卫星影像；尚未接入真实建筑模型、地形或数字孪生。相机到达后启动三维落镜，日夜连续过渡，支持拖动环绕、缩放和减少动态偏好。
- 地图手势由 GPU 引擎处理，不逐帧更新 React；像素比上限 1.5，建筑/座椅实例化，三维场景隐藏及页面后台时暂停 RAF，卸载释放 GPU。未承诺所有实体手机达到固定帧率。
- “往期”仅由北京时间下的日期判定；本人是否到过依赖账号下手动保存的到场记录。

## 接口与兼容

- `GET /api/footprints/catalog`：公开目录，含 `cities`、艺人、场次、来源、`verified_on` 和服务端北京时间 `today`。
- `GET /api/footprints`：当前账号的 `event_id[]`。
- `PUT /api/footprints/{event_id}`：`{attended: boolean}`；成功返回本人完整 `event_id[]`。未来日期不可标记到场。
- `GET /api/playlists`、`GET /api/playlists/{id}`：只读本人收藏快照，跨账号详情返回 404。
- `PUT /api/playlists/concerts/{event_id}`：幂等收藏目录内曲目；无曲目或未收录场次返回 422，未登录返回 401。
- `GET /api/stories?event_id=...`：只显示这个日期的已公开快照。
- 保留原有六个 `event_id` 和记忆关联。`/footprints?event=...` 直接进入对应夜空；`/?event=...` 保留记录入口，登录返回链接保留艺人、城市、场馆和日期。

读取失败时阻止误写；保存不做乐观更新，失败保留原状态。卸载或切换账号终止旧请求并忽略迟到结果。前端验证全国复位、空城市、日期切景、目录 QQ 域名兼容、界面移除音乐外链、未来到场禁用、重复点击和旧响应；后端覆盖归属、北京时间跨日、歌单快照和服务重启后的收藏持久化。
