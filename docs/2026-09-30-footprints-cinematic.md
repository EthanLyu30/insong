# 足迹写实重构：设计、实施与验收

## 当前版本：用户选定图 1 外景与图 3 内景

本节覆盖下文旧模型版本的场景实现描述；旧记录保留为过程历史。用户选定的连续体验已改为：全国真实卫星地图 → 拉近后呈现日落场馆外景 → 再点击场馆进入星光现场。外景和内景统一使用浅色 44px 圆形返回／地图按钮，底部保留精简场次与可收藏曲目列表。

场景使用两张生成的无 UI 概念素材（`frontend/public/scenes/stadium-exterior.webp`、`stadium-interior.webp`，均为 780×1688），Three.js 显示带有限深度的照片表面。拖动与按钮允许小范围景深变化和拉近，切景交叉淡入；相机静止、页面隐藏或返回地图后不持续渲染。减少动态模式直接呈现终点。素材为通用示意，不是选中场馆的真实照片或建筑测绘，也不支持任意 360° 环绕。

全国地图继续使用真实地理数据和原生 MapLibre 手势，统一暖白控件、铜色行程入口、浅金城市灯点；全国视野针对竖屏避开顶部搜索与底部面板。城市标记在低倍率防碰撞，放大或搜索仍可选择城市。没有把生成效果图内不准确的地理轮廓用于地图。

本轮回归修复：9–12 首歌改用可滚动星区，避免复用 8 个坐标；记录全过程的拖动状态，避免往返拖动误入场馆；小屏长星区限制在歌单上方；小屏舞台上移避免被面板遮住；部分纹理加载失败时释放已成功加载的资源并降级为静态图。收藏仍使用既有服务端快照与账号隔离接口。

最终浏览器画面和与选定方案的对照见 [design-qa](../design-qa.md)。后文原三维模型与 SceneFlight 测试只描述前一轮实现，不代表当前照片景深场景。

## 用户意图

沿用全国 → 场馆 → 演唱会星空的路径，撤掉卡通表现。用户要求真实感、连续运镜、3D 动态交互、流畅地图缩放；歌曲直接列出，不显示资料出处或外站跳转；一键把场次曲目收藏为个人歌单。

## 设计与取舍

1. 推荐并实施：MapLibre WebGL 卫星底图 + Three.js 三维场馆、天空。地图常驻，不随层级重建；城市与场馆通过 flyTo/easeTo 连续推进；三维场馆从高空建立镜头、落到倾斜环绕视角，选择场次时灯光与天空连续入夜。地图拖动缩放不写入 React 状态。
2. 保留 SVG 再加纹理：成本低，但没有真实空间与渲染性能，无法满足本次修改。
3. 全量真实城市数字孪生：需要可用的建筑模型、地形与服务许可，目前项目没有这些资源。采用真实影像和原创物理材质三维场馆，明确模型并非场馆精确复刻。

全屏构图、轻量毛玻璃控制、城市灯点与行程航线。首屏只显示一个近期场次；场馆面板显示最近场次；星空只显示曲目与收藏，资料仍留在目录和技术文档，产品页不摆出处或音乐跳转。长曲目列表可滚动，星星可选择对应曲目。

收藏由服务端按 event_id 从可信目录生成快照（标题、艺人、曲目、资料类别），不接受客户端曲目。owner_id + event_id 唯一，重复点击不重复创建；登录才能收藏；我的歌单能找回内容，服务重启后仍在。不承诺同步到 QQ 音乐账号。

## 审查关注

路线更新不重建地图；场次链接优先决定地点；无法定位的场馆不冒充精确定位；导入或渲染失败仍能选城市/场次；收藏换用户/换场次不串数据；地图和三维 renderer 不遗留 RAF 或 GPU；性能测量只报告实际浏览器数据，不保证所有实体设备帧率。
