# Task 3：演示身份与服务端私密读取设计

## 目标与范围

为「歌里有我」H5 Demo 提供小林、阿远和访客三种可见身份，让两位演示者能在同一设备切换，也能在两个独立浏览器会话中验证私密记忆不会跨帐号泄露。身份的事实来源是后端会话，不是前端状态或请求中的用户 ID。

Task 3 完成登录、登出、当前身份、顶部帐号切换，以及一个受服务端权限保护的记忆详情读取接口。创建、编辑、删除、公开、撤回、列表与搜索仍属于 Task 4—6；本阶段不把它们伪装成已完成。

## 身份模式与限制

- 使用现有 Seed 用户：ID 1 小林、ID 2 阿远，均须有 `is_demo=true`。访客没有会话。界面始终标注「演示帐号，仅用于黑客松功能验证」。
- `POST /api/demo/sessions` 接收 `{"user_id": 1}` 或 `{"user_id": 2}`。后端只允许选择当前数据库中存在的这两个演示用户；不接受任意用户 ID，也不从请求正文读取后续操作的所有者身份。
- 这是受控演示帐号切换，不是正式注册或具有密码的登录。知道接口的人仍能主动切换为小林或阿远，因此不得将其描述为真实用户的身份安全方案，也不向普通用户开放。
- `GET /api/me` 返回当前身份；访客返回 `{"user": null}`，而不是把访客当作请求错误。`POST /api/demo/logout` 幂等，返回 204 并清除 Cookie。

## 服务端会话与 Cookie

- 登录时使用安全随机数生成不可预测的会话值。浏览器只收到该值的 Cookie；数据库 `Session.id` 保存其 SHA-256 摘要和关联用户 ID，不保存明文会话值。会话持续 24 小时，服务端每次读取时检查 `expires_at`。
- Cookie 为 `HttpOnly`、`SameSite=Lax`、`Path=/`，并设与服务端有效期一致的 `Max-Age`。本地 HTTP 演示不使用 `Secure`；通过 HTTPS 提供服务时设置 `Secure`。前端不读取或存储会话值，只在 API 请求中携带 Cookie。
- 切换帐号时使原会话失效，再创建新会话。登出删除服务端会话并清除 Cookie；复制旧 Cookie、伪造 Cookie 或使用过期会话都只能得到访客身份。
- 请求处理将「可选当前用户」「必须登录的用户」「可读某张记忆卡」集中为可复用的后端权限函数，供 Task 4—6 继续调用。会话和权限不依赖前端隐藏按钮。

## 记忆读取权限

- 提前实现 `GET /api/memories/{id}` 作为 Task 3 的最小权限验证入口。本人可读取自己的 `private` 或 `public` 卡；其他帐号和访客只可读取 `public` 卡。
- 对不存在的卡，以及非作者访问 `private` 卡，统一返回 404 与「这段音乐记忆已经不可见。」。不以 403 暴露私密卡是否存在。
- 成功响应仅包含卡片公开展示与本人回看所需字段：ID、作者 ID 与昵称、歌曲 ID、故事、Tag、人生时间、场景、可见性、演示样例标记、创建和修改时间。不返回会话或其他用户的私人数据。
- Task 3 不新增公共列表或搜索接口。后续歌曲故事、发现与分享读取必须复用同一可见性规则；撤回公开的端到端验证留到 Task 5—6。

## 前端体验

- 在现有 H5 顶部加入「切换演示帐号」入口，提供小林、阿远和访客。当前身份从 `/api/me` 获取，刷新后由 Cookie 恢复，不使用 `localStorage` 保存会话。
- 切换时调用登录或登出 API，再重新获取当前身份；等待与失败有中文反馈。访客进入「我的记忆」显示需切换演示帐号的提示，而不是空白页。
- 现有歌曲浏览继续对访客开放。创建页和我的记忆主体仍保持后续 Task 的真实未完成状态，不提前展示虚假的可写功能。

## 验证

- 后端用独立临时 SQLite 文件和两个独立 HTTP 客户端测试：小林登录后可读自己的私密卡；阿远和访客通过直接 URL 均得 404；三者可读公开演示卡。
- 检查登录只能选有效演示帐号、Cookie 属性、刷新／重启后的会话读取、帐号切换与登出后的旧 Cookie 失效、伪造和过期会话按访客处理。
- 保持 Task 1—2 歌曲 API 和 Seed 行为；运行完整 `pytest`、真正的 `npm run build`、`git diff --check`。只提交 Task 3 文件，不提交数据库、Cookie、令牌或用户未跟踪的旧 PRD。
- 所有工作在 `main` 分支进行。功能验证完成后提交 `feat: add demo auth and privacy rules` 并通过现有 HTTPS／7897 连接推送；推送失败即停止，不开始 Task 4。
