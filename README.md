# 歌里有我

一个可以操作的音乐记忆 H5：**选中一段音乐 → 留下一句经历 → 私密保存 → 用自己的线索找回 → 从原位置重听**。

## 已实现

- 温暖明亮的首页，保留五张卡片和中央手机的构图、透视及手写字体；卡内画面轮播可暂停。
- 5 首各 48 秒的原创器乐样例，真实播放、进度拖动和片段标记。每首歌绑定固定版本资源。
- 个人用户名与密码注册、登录、退出；数据库保存账号和记忆，密码使用加盐 PBKDF2 哈希。
- 记忆默认私密；一句话即可保存，播放位置、人生时间都可不填。创建支持请求去重，编辑、删除和补记有版本冲突检查。
- 我的记忆列表、按歌曲筛选、同首歌的多次记录，以及保留原文的“今天补一句”。
- 本人记忆关键词查找和本地 E5 语义检索；返回原文候选，用户自行确认。模型缺失、忙碌或超时会明确降级到关键词。
- 服务端按账号限制列表、搜索、修改、删除；切换身份会清空当前页面数据。小林、阿远仍是**所有体验者可进入的共享样例账号**，请只输入虚构文字。

[PRD v2](docs/歌里有我_PRD_v2_差异化方案.md) 是本次实现的产品依据，其中第 11 节保留的是修订时的代码快照；最新运行状态以本 README 为准。

## 体验路径

1. 首页选择歌曲，打开歌曲页并试听，点击“留住当前…”标记位置。
2. 点击“留下一刻”，创建个人账号或进入共享样例账号；写一句经历，时间可以写“去年夏天”，也可以空着。
3. 保存后刷新页面，原文和位置仍在。进入“我的记忆”，使用关键词或换一种说法查找。
4. 打开候选，点击“从 00:xx 重听这一段”；也可以编辑原文、另补一句，或确认删除。

## 本地启动（Windows PowerShell）

```powershell
cd backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开终端：

```powershell
cd frontend
npm install
npm run dev -- --host 127.0.0.1
```

打开 `http://localhost:5173`。Vite 代理 `/api` 到本机后端；同源访问保留会话 Cookie。当前会话有效期为 24 小时，过期后重新登录。SQLite 位于 `backend/data/demo.db`；启动会增量补齐旧表字段，不重置已有内容。请保留该目录。

macOS/Linux 用 `python3` 创建环境，然后使用 `.venv/bin/python`、`.venv/bin/hf`，其余命令相同。

### 启用本地语义找回

首次安装后，在 `backend` 目录下载固定版本的公开模型：

```powershell
.venv/Scripts/hf.exe download Xenova/multilingual-e5-small onnx/model_quantized.onnx tokenizer.json config.json tokenizer_config.json --revision 761b726dd34fb83930e26aab4e9ac3899aa1fa78 --local-dir models/multilingual-e5-small
```

模型文件不入 Git；在本机保留供推理使用。下载连接 Hugging Face，**检索时的私人文字和查询只在应用后端本机处理，不发送给模型服务商**。`GET /api/search/status` 返回模型文件是否就绪。模型的 [ONNX 版本](https://huggingface.co/Xenova/multilingual-e5-small) 源自 [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small)。

语义检索有 5 秒等待上限，同时只运行一个模型任务；忙碌、缺文件、初始化或推理失败时走关键词。每次仅从当前账号记录计算向量，无私人正文向量文件或跨用户正文缓存。原文很长时分段编码，返回前再次检查所属账号、记录版本及是否删除。

相似度阈值 0.865 是小样例试验后的初值，不是“86.5% 置信度”；仍会漏找或误匹配。例如“现场结束了还不想回家”可能同时找到演唱会和毕业晚会，必须由用户确认。尚未完成 PRD 中的 50 条独立评测和真实用户对照，不能据此声称 AI 优于普通检索。

## 资源与产品边界

- 音频是本项目生成的原创器乐练习，来源与版本见 [media/README](backend/media/README.md)。歌曲名称为虚构样例，没有真实 QQ 音乐曲库、歌词、平台账号或播放器接入。
- 公开摘录、发布撤回和陌生人共鸣尚属 PRD 后续阶段；这次完成私人保存、找回和片段重听。旧种子公开卡仍是明确标注的样例，新卡一律私密。
- 个人账号是独立站点账号，暂无密码找回、端到端加密或生产托管。部署前应补齐 HTTPS、域名/Origin 配置、账号恢复、备份、滥用防护及完整授权资源接入。本地服务默认绑定回环地址。
- 人生时间目前保存用户原话并按记录创建时间列出，可按歌曲筛选；不把“去年夏天”等模糊时间伪装成准确日期。结构化人生时间排序、时间筛选留待下一步验证。
- QQ 音乐实测与自发回访研究尚未完成，不宣称平台首创或已经验证长期需求。

## 验证

```powershell
cd backend
.venv/Scripts/python.exe -m pytest -q
# 另一个终端，在 frontend：
npm test
npm run build
```

后端覆盖：旧库升级、注册与会话、账号隔离、请求去重、冲突反馈、编辑/补记/删除、关键词与语义降级、原文依据、无结果、音频 Range 请求。删除后保留不含正文的请求回执，避免编号复用和网络重试复活已删除内容。前端覆盖时间输入、登录返回地址、API 错误处理，以及切页/切账号后旧响应不能覆盖新草稿。

本次已在浏览器实测虚构记忆的保存、刷新、00:12 片段重听、编辑、补记、删除、本地模型查询与无结果，以及个人账号注册后的空白空间和退出。390px 手机宽度无横向溢出，筛选按钮不折行。临时验收记录与账号已清理。模型查询暴露了候选混淆，已在结果页保留原文确认与关键词入口；这些是功能检查，不是真实用户价值实验。
