# 歌里有我

2026-10-02 更新：清理旧图片引用，记忆样例改为多张照片；场馆夜场恢复各自的虚拟场景并明确标注。4 张近期实拍仅用于适配的配图和预览。首页保留原构图、动态与手写字体，封面/背景改为原分辨率 WebP，字体增加完整字符集 WOFF2；图片与字体首次传输合计从约 17.1 MiB 降至 3.2 MiB。

一个面向歌迷的音乐记忆 H5：**歌曲或现场 → 照片与故事 × 音乐位置与记录时间 → 私密保存 → 时间轴回看 → 自愿公开完整原文 → 按歌手、歌曲、标签或经历发现共鸣 → 重听对应片段**。

最新界面按用户提供的 12 页《9.29修改意见总结.pdf》落实；见[实录预览](docs/fan-music-cards-20261001.png)。下方历史方案说明中的交互，以本 README 当前实现和[验收记录](design-qa.md)为准。

## 已实现

- 记录离开保护：新建记忆离开时可继续编辑、存草稿并离开或放弃；已有记忆的编辑提供继续／放弃修改。站内跳转和浏览器返回均受保护，刷新或关闭页面使用浏览器提醒。保存尚未完成时保留编辑页等待结果；选歌往返、照片上传和弹层关闭不会绕过保护。仅自动预填演出信息仍不能保存空草稿。
- 演出记录从具体场次预填日期和“城市 · 场馆”，保留用户修改及已存草稿的时间地点。保存时由后端冻结演出名称、歌手、日期、城市和场馆，私人详情、主动公开的故事与编辑均沿用该快照；日程改期或移除不会覆盖旧记录。旧数据库自动增加字段，已有记录按仍可找到的日程补齐一次，无法重建已经丢失的历史资料。[手机端实录](docs/record-flow-protection-20261006-preview.jpg)。

- 温暖明亮的沉浸首页，保留五张卡片和中央手机的构图、透视及手写字体。顶部品牌和底部四栏导航始终可见，动态拼贴占主体区域的 3/4。按用户要求恢复原版彩色封面和选歌交互；点击卡片选择歌曲，中央手机打开歌曲入口。普通首页始终保持同一完整构图，从其他模块返回也不会缩小或换成长文案；空白与“翻开我们的音乐故事”按钮进入独立共鸣页。主题选歌入口保留；夜场记录直接打开创建表单。[返回首页实录](docs/hear-home-consistent-20261001.png)
- 5 首各 48 秒的原创器乐样例，真实播放、进度拖动和片段标记。可选起止区间，播放到终点自动停止；没有区间时播放整首。每首歌绑定固定版本资源。
- 个人用户名与密码注册、登录、退出；数据库保存账号和记忆，密码使用加盐 PBKDF2 哈希。
- 创建和编辑记忆时可设置“仅自己可见 / 公开可见”，新建默认私密。选择公开并点击发布或保存时，公开当前编辑区的完整正文、标题、照片、标签和关联演出；不沿用旧的公开片段。新建的原卡与公开快照在同一事务中创建；编辑先保存原卡，再按返回的新版本确认公开，公开失败会保留正文并显示状态，重试使用已保存的版本。匿名和时间公开设置保留原选择，新建默认匿名且不公开时间。创建请求去重、版本冲突和转私密撤回检查继续保留。
- 左侧时间轴、宽幅图文卡、日期在正文上方；完整文字不截断，可按自己留下的经历标签（演唱会、音乐节、跨城追星等）筛选，选项来自本人已有记忆，同一段经历可有多个标签。未加标签的记录可单独找回，不从正文或歌曲猜分类。私人详情的标签找回个人同类记忆，公开故事的标签用于发现听友故事。同首歌仍可多次记录；旧歌曲筛选链接显示可清除的配乐条件，改选经历后移除此条件。筛选及阅读视图随详情返回保留，无匹配结果可一键查看全部。年份由用户填写，未标年份单独显示。个人回忆搜索从页面移除，旧补记继续保留。
- 卡片支持选填标题、最多 8 个标签、最多 9 张照片，封面从所上传照片中选择；删除封面时顺延到剩余照片。详情按照片网格展示，支持大图、切换与 Escape 关闭；没有上传照片时使用歌曲配图。照片经校验、缩放与移除元数据后保存，只有本人或当前有效公开快照的读者可以访问。
- 3 个歌迷记录主题：散场以后、音乐节的夏天、跨城去见你；主题会从选歌一路带到记忆卡。推荐区连接已收录近期现场，排除取消日期，显示具体时间和状态；尚无热度数据，不声称热门排名。每个原创样例录音仍有 3 句示例词句，用于演示逐句定位。
- 可见范围在编辑页设置，打开页面或切换选项不会发布。主动公开保存时使用编辑区完整原文；已有历史公开片段不会自动扩展，只有本人再次公开保存才更新。修改原卡先撤回旧快照，确认公开后建立新快照；补记仍仅自己可见。
- 面向访客的“共鸣”页面：歌手、歌曲、活动、标签关键词搜索与可选经历匹配；两列照片卡突出歌名、歌手及故事标题。标签可直接点击，关键词搜索返回全部匹配，标签页二次搜索保留标签约束。点击照片或标题直接进入独立详情页，完整公开原文与相册在详情阅读；列表不再翻面或自动播放。详情使用用户提供的手写字体。歌曲页用“听友故事 / 我的记忆”切换公开故事与本人记录，另设一个“写记忆”入口；移除重复的滚动按钮和“音乐卡片”跳转。查看故事、记忆或取消创建后，返回实际来源并保留歌曲视图及所选片段；旧歌曲、歌词、标签筛选页也提供返回入口。保留大图、播放控制、片段定位和重听。
- “我的”中的“足迹”：移动端整屏原生地图，47 个省会／主要城市可浏览、拖动和缩放。点已知场次直接进入对应星空；点地图歌手头像先看当地场次列表，再点场次进入星空。当地列表保留月份／时期筛选、歌手／日期搜索、连场合并、歌手关注及场次收藏，返回保留原筛选、搜索和列表滚动位置。夕阳外景屏及入场入口已移除，旧 `scene=venue` 链接若指定有效场次则直接进入星空。目录收录 7 位歌手／组合、84 条日期记录、16 个场馆及 3 条取消记录。星空按场馆匹配内景，封闭体育馆保留屋顶；进入星空只下载内景贴图，保留受像素约束的景深手势、歌曲星星、歌单收藏及现场记忆入口。
- 公共经历匹配使用本地 E5；返回获准公开的原文候选，用户自行确认。模型缺失、忙碌或超时会明确降级到关键词。原有私人检索 API 保留兼容，当前个人记忆页面不再展示该功能。
- 服务端按账号限制列表、搜索、修改、删除；切换身份会清空当前页面数据。小林、阿远仍是**所有体验者可进入的共享样例账号**，请只输入虚构文字。

- 足迹默认往期，“接下来”仅含北京时间今天起七个自然日；可按年月筛选。同一歌手、巡演和场馆仅相邻自然日合并连场；列表上下滚动，搜索可按歌手和日期。取消／改期提示保留，核验日期保存在目录、不占用界面。点击场次行即可靠近场馆地图，删除重复的“靠近这场现场”按钮。
- 移除“我关心”和想去入口；选中歌手后，行程标题旁可独立关注或取消关注。歌手关注、具体场次收藏、到场和歌单分别按账号保存。
- 收藏歌单保留原曲目、顺序、资料类型、核实日期及版本；资料更新时显示提示，由用户点“更新这张歌单”后替换。重复收藏和普通读取不会覆盖；冲突时重新读取本人已保存版本，须再次主动确认。旧收藏继续可读，明确标为曲目类型待核实，不继承目录中的新核实状态。

- 足迹歌曲星群按场次生成稳定的错落位置，星点大小和闪烁节奏有变化，保留歌名之间的间距；点击播放和展开歌单不会重新打乱位置。小屏可轻滑浏览剩余星点，系统减少动态效果时关闭闪烁。
- 足迹标题、导航按钮、星群和歌单按 H5 容器宽度定位；电脑窗口保持同一布局，避免宽屏规则把内容撑出页面。歌单与底部导航共用安全区高度。已检查 320–1042px 六种窗口宽度及歌单收起、展开、滚动和返回。[手机端实录](docs/footprints-responsive-20261006-preview.jpg)。
- 足迹总览显示“返回我的”，点头像进入当地列表后显示“返回地图”，逐层返回。右上歌单入口保留原地图及“我的”筛选；空歌单返回原地图，歌单详情进入星空也保留这些信息。直接打开城市链接时，关闭城市先回总览。[返回入口实录](docs/footprints-back-navigation-20261006-preview.jpg)。
- 本地资料维护工具可预览新增、改期、取消、场馆、歌单及音源变化，核对后按旧版本SHA写入并保留审核记录。旧ID不能删除；真实歌单必须有对应场次证据，音源需另附来源。尚未启用自动采集或AI提取，详见[资料维护](docs/footprints-data-maintenance.md)。

[双坐标音乐记忆 v3](docs/双坐标音乐记忆_v3.md) 保留产品主轴；本次交互和页面以用户提供的《9.29修改建议.docx》、[9.29 改版说明](docs/2026-09-29-product-redesign.md)及本 README 为准。[PRD v2](docs/歌里有我_PRD_v2_差异化方案.md) 保留为历史方案。新增日期、场馆和取消记录的证据见[目录来源核对](docs/footprints-catalog-sources.md)，模块评价与下一步取舍见[足迹评审](docs/footprints-review-20261001.md)。

## 体验路径

1. 首页点击音乐卡片进入故事，或点空白／按钮进入推荐页；从故事、歌曲或主题进入记录。
2. 下方中央“＋记录”直接打开创建表单，先写标题、经历或添加照片，再通过表单内“添加配乐”搜索所需歌曲；不再铺开推荐或最近列表。选歌不跳页，更换配乐保留正文、照片和时间信息，并清除前一首歌的词句和播放位置；保存前需选定配乐。搜索使用已收录曲库，尚未接入 QQ 音乐全曲库。歌曲／故事入口可继续携带已选歌曲和片段进入创建。个人记忆页面负责浏览，不再有头部加号。标题、标签、照片和封面、年份、时间备注、词句与播放区间按需填写，创建时可选择私密或公开；匿名和时间公开选项在“补充细节”中按需展开，由“发布”确认。“词句与片段”和“补充细节”按需展开；既有主题关联保留，保存不依赖主题服务。
3. 在“我的记忆”按经历标签筛选，或沿左侧时间轴找回卡片；打开详情，看完整原文与照片。正文卡片后紧接“编辑”和“删除记忆”，配乐与补记置于其后；删除需再次确认，失败可刷新最新版本后重新确认。经历标签、月份及演示身份筛选使用与触发器等宽的暖色选择面板，贴合控件、按空间向上或向下展开，屏幕变化后锚点离开可视区会关闭。移除三点菜单及重复的“这首歌里的其他时刻”入口。页面移除配图来源展开区、AI 配图说明及重复录音资料，图片来源元数据仍保存在代码和资料文档中。
4. 创建或编辑记忆时，在“可见范围”选择公开并点击发布或保存，完整正文会公开；署名与时间保持原设置。仅打开编辑页、切换选项或取消编辑不会改变已有公开内容。旧卡曾只公开部分原文时，本次主动公开保存会替换为编辑区中的完整原文。
5. 进入“共鸣”，输入相近经历，点卡片进入详情，看公开原文并按需播放。若选了 00:10–00:14，播放会在 00:14 停止；未选区间则播放整首。
6. 在“足迹”点具体场次，直接进入对应星空。也可点地图头像，打开该歌手的当地场次列表，再点场次进入星空；列表可上下滑动，按歌手或日期搜索，只有相邻自然日合并为连场。返回回到原列表，保留月份、时期、搜索和滚动位置；直接打开夜场链接且没有站内前页时，返回该歌手的当地场次。取消记录保留提示，不能从列表新增入场或到场。点星星或曲目列表选歌，“收藏为歌单”保存到“我的现场歌单”。“记下这一晚”直接打开创建表单，保留具体场次 ID；连场各晚不会串场。“同场记录”可标记往期到场、查看已主动公开的记忆。当前现场歌单尚未确认时仍明确标注为关联作品。[当地场次实录](docs/footprints-local-concerts-20261006-preview.jpg)。
7. 在编辑页选择仅自己可见并保存。公共直链、搜索与照片公共访问失效，原文仍在个人空间。编辑正文先撤回旧快照，若选择公开并保存则以新版本重新公开完整正文；公开失败时保留已保存内容、提示重试。删除同时移除私人卡和公开内容。

## 本地启动（Windows PowerShell）

使用 Python 3.12、Node.js 22.12 或更高版本。基础体验不需要模型、GPU、QQ 音乐密钥或本机旧数据库。先确认 `python --version`、`node --version` 正常。

开发中的最新修改先推送到 **lxy**，由作者手动合并到 main。新协作者可在空目录执行（浅克隆跳过历史大图）：

```powershell
git clone --branch lxy --single-branch --depth 1 https://github.com/Saskia-1/TME.git
cd TME
```

在仓库根目录打开两个终端。后端：

```powershell
cd backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开终端，仍从仓库根目录开始。前端优先按已提交的锁文件安装：

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1
```

没有 pnpm 时先运行 `npm install -g pnpm@11.19.0`。也可用 `npm install`、`npm run dev -- --host 127.0.0.1`，但 npm 不读取 pnpm 锁文件，依赖版本可能不同。原生 MapLibre 使用 Esri World Imagery 卫星影像，叠加 Mapterhorn 地形阴影和 OpenFreeMap / OpenStreetMap 矢量道路，无需地图密钥；网络不可用时底图不能正常呈现，会显示提示；本地地点、日程、场馆与歌单仍可操作，不再等待外部瓦片就绪。Three.js 与所选场馆内景贴图在进入星空时才加载，署名可在地图信息按钮中查看。三维场景需要 WebGL 2，不支持时保留城市、日程与歌单操作。

打开 `http://localhost:5173`。Vite 代理 `/api` 到本机后端；同源访问保留会话 Cookie。当前会话有效期为 24 小时，过期后重新登录。SQLite 位于 `backend/data/demo.db`；启动会增量补齐旧表字段，不重置已有内容。请保留该目录。

macOS/Linux 用 `python3` 创建环境，然后使用 `.venv/bin/python`、`.venv/bin/hf`，其余命令相同。

### 启动或加载很慢时

| 卡在哪里 | 如何区分与处理 |
| --- | --- |
| `git clone` / `git pull` | 查看终端停在网络连接还是对象下载。仓库有图片、字体和音频，首次克隆可用上面的 `--depth 1`。Git 历史仍包含以前的大图，优化当前文件不会缩小旧历史。 |
| 依赖安装 | 基础版只安装 `requirements.txt`；不要先下载可选模型。保留安装失败的最后几行，区分网络、Python/Node 版本和包安装错误。 |
| 页面一直加载 | 两个终端都要保持运行；访问 `http://127.0.0.1:8000/api/songs` 应能看到歌曲 JSON。读取请求最多等待 12 秒，保存/上传最多 30 秒；超时可重试。保存超时不代表服务端未写入，先查看最新状态。 |
| 首页有图，足迹底图慢 | 场馆图片在仓库内，卫星/街道瓦片来自外部地图服务。这是不同的资源链路。外部服务慢时仍能通过场次直接进入本地星空场景。 |
| 某张图不显示 | 浏览器 Network 查看是否 404，以及具体 URL。`frontend/public` 图片与字体、`backend/app/sample_photos` 样例照片、`backend/media` 原创音频均随代码提交。用户上传的照片存放在 SQLite，其他人的新数据库不会包含你的私人照片。 |

开发和构建预览固定使用 5173；被占用时明确报错，不会悄悄换端口造成登录/保存失败。检查占用的终端后再启动。测试构建版可先停开发服务，再执行 `pnpm build`、`pnpm preview --host 127.0.0.1`；预览也代理到 8000 后端。

### 启用本地经历匹配（可选，先确认基础版能打开）

基础安装不包含 ONNX、分词器及模型下载工具；缺少模型时仍可浏览、记录、播放原创样例、搜索关键词、使用足迹。仅需要本地语义匹配时，在 `backend` 目录额外安装并下载：

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-ai.txt
.venv/Scripts/hf.exe download Xenova/multilingual-e5-small onnx/model_quantized.onnx tokenizer.json config.json tokenizer_config.json --revision 761b726dd34fb83930e26aab4e9ac3899aa1fa78 --local-dir models/multilingual-e5-small
```

模型文件不入 Git；在本机保留供推理使用。下载连接 Hugging Face，**检索时的私人文字和查询只在应用后端本机处理，不发送给模型服务商**。`GET /api/search/status` 返回模型文件是否就绪。模型的 [ONNX 版本](https://huggingface.co/Xenova/multilingual-e5-small) 源自 [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small)。

语义检索有 5 秒等待上限，同时只运行一个模型任务；忙碌、缺文件、初始化或推理失败时走关键词。个人搜索仅使用当前账号记录；公共搜索仅使用已发布快照中的原文片段、获准分享的时间备注和歌名。无私人正文向量文件或跨用户正文缓存。长文分段编码；返回前重新检查权限、发布状态及版本，避免推理期间撤回后返回旧内容。

相似度阈值 0.865 是小样例试验后的初值，不是“86.5% 置信度”；仍会漏找或误匹配。例如“现场结束了还不想回家”可能同时找到演唱会和毕业晚会，必须由用户确认。尚未完成 PRD 中的 50 条独立评测和真实用户对照，不能据此声称 AI 优于普通检索。

## 资源与产品边界

- 5 首音频是本项目生成的原创器乐练习，来源与版本见 [media/README](backend/media/README.md)；这些录音名称与逐句定位文本为原创演示素材，没有人声演唱。另增周杰伦《稻香》、邓紫棋《光年之外》《泡沫》、刘雨昕《REALITY》、五月天《倔强》的真实歌曲元数据，配以明确标注的虚构故事与场景插画。这些歌的音源尚未接入，界面明确提示不可播放，不用原创器乐代替歌手录音。没有真实 QQ 音乐曲库、歌词、平台账号或播放器接入。
- 旧公开种子卡一次性迁移为公开片段，原始记忆接口改为本人可读；原本私密的卡不会迁移到公开。撤回后重启服务不会再次公开。共享样例账号内的操作仍由所有体验者共享，个人真实记录请使用个人账号。
- 浏览器草稿尚未同步云端；同一账号在同一浏览器地址下只保存最近一份，再次“存草稿”会替换旧稿。`localhost` 与 `127.0.0.1`、不同端口属于不同浏览器存储范围，找回时需使用保存时的地址与账号。清除站点数据、更换浏览器或设备后不能从服务器找回；正常新建和退出登录不会主动删除其他已存草稿。
- 个人账号是独立站点账号，暂无密码找回、端到端加密或生产托管。部署前应补齐 HTTPS、域名/Origin 配置、账号恢复、备份、滥用防护及完整授权资源接入。本地服务默认绑定回环地址。
- 时间轴按用户填的年份降序排列，同年按记录创建时间排列；未填年份另列。保留“去年夏天”等用户原话，不推断准确日期。
- 足迹是截至 2026-10-01 核对的部分场次目录，并非全国实时演出数据。84 条记录含历史场次及 3 条取消记录，81 条未标取消不等于全部实际举行。16 个场馆有带来源的 WGS84 坐标，部分为公共建筑轮廓中心，不代表出入口测绘精度或导航终点。地图使用 Esri 卫星影像、DataV GeoAtlas 省界、OpenStreetMap 街道和 Mapterhorn 地形阴影。默认显示往期；“接下来”只含北京时间今天起七个自然日（今天至第六天），更远的计划不会混入。同一歌手、巡演、城市和场馆仅相邻自然日合并成连场，空一天即另起一组（如 09.25–09.27 与 10.01–10.02 分开）。当地场次列表上下滚动，无逐日横向按钮或“全部场次”；搜索支持歌手及精确日期，具体日期保留独立 ID。月份、时期筛选和直接链接的指定夜晚仍生效，歌单、到场和记忆不会因合并串场。界面移除核验日期，取消和改期提示保留，来源与核验数据仍在目录中。移除“我关心”和想去入口；选中歌手后可关注或取消关注，在“我的歌手”筛选中找回。歌手关注与场次收藏分别保存，保留真实到场、歌单收藏与记忆关联。夜场中央三角收起整块歌单，只留展开三角，音频状态和收藏组件保持挂载。
- 夕阳场馆屏已移除，进入星空仅加载所选场馆的虚拟内景灯海；未知场馆不套用其他城市图片。旧外景资源保留为历史设计资料，运行时不再预加载。360° 无人机环绕仍停用，夜场仅保留受源像素约束的景深手势，拖动范围限制在水平 ±12°、俯仰 ±7°，缩放按原图分辨率限制。地图与星空过渡共用原生画布，返回淡出夜场，避免残留图片遮住地图。输入、资源加载和过渡期间才重绘，手机尺寸变化与地图绘图缓冲同步。
- 星空和收藏目前使用目录内的歌手关联作品，尚未核实实际演出曲目；资料类别与原始出处留在目录和来源文档，界面按用户要求只列曲目。不可在投稿中宣称这些是已确认的完整现场歌单。收藏是本项目账号内的曲目快照，不会同步创建 QQ 音乐歌单；目录资料更新不会悄悄覆盖，用户选择更新时会核对收藏版与目录版，替换为最新已审核资料。用户确认暂无比赛 QQ 音乐播放接口或歌手音频文件，因此现有歌手曲目显示“暂缺音源”。播放器已用项目原创音源实测真实播放；没有把原创器乐伪装成歌手录音。接入时为目录中相应曲目提供 `audio_url` 和可选 `audio_label`，支持本站 `/api/audio/…` 或可直接播放的 HTTP(S) 音频地址；QQ 搜索网页不是音频地址。完整第三方曲库与账号授权仍需另行接入。
- 照片支持 JPEG、PNG、WebP，单张不超过 5 MiB；数据库内存储最长边不超过 2048px 的净化 JPEG。公开卡撤回后照片立即失去公共访问资格；删除记忆不自动清除未再引用的照片，当前没有用户照片库或孤立照片自动回收功能。
- QQ 音乐实测与自发回访研究尚未完成，不宣称平台首创或已经验证长期需求。
