# 歌里有我

面向歌迷的音乐记忆 H5，以手机端体验为主。把照片、文字和歌曲留在具体的一晚，先为自己保存，再自行决定是否公开；通过时间、地点或相近经历，重新找到那段记忆。

**核心流程：歌曲或演出 → 记录照片与故事 → 私密保存或公开发布 → 找回记忆 → 发现听友经历 → 回到音乐。**

## 核心功能

### 记录与回看

- 创建、编辑、删除记忆，支持标题、正文、配乐、时间、地点和经历标签。同一首歌或同一场演出可记录多次，演出关联为选填。
- 正文最多 500 字，每条记忆最多 9 张照片、8 个标签；可选择封面，查看相册大图。
- 从演出进入记录时预填日期和场馆；连场可选择实际参加的那一晚。保存后保留场次信息快照，目录改期或移除不会覆盖已有记忆。
- 未收录的歌曲和演出可手动填写，个人补充资料不加入已核实日程。
- “我的记忆”支持时间轴、足迹视图，以及经历标签、时间、城市筛选和文字搜索；详情中的编辑、删除操作紧接正文卡片。

### 草稿与内容保护

- 创建页右上角“草稿箱”可查看、继续编辑和删除多份草稿；“我的记忆”有草稿时也显示入口。
- 空白内容、仅自动预填场次或单独选择配乐时不能存草稿。正式保存需要填写正文并选定配乐。
- 新建内容离开时可继续编辑、存草稿并离开或放弃；编辑已有记忆时可继续或放弃修改。站内跳转、选歌页退出和浏览器返回均有保护，刷新或关闭页面使用浏览器提醒。
- 保存失败保留编辑内容；保存成功只清除当前对应草稿。

### 私密与公开

- 新建默认“仅自己可见”，创建和编辑时均可改为公开；只有点击发布或保存后才生效。
- 公开内容包含当前正文、标题、照片、标签及关联演出，支持匿名和时间公开设置。
- 转为私密、撤回或删除后，公开直链、搜索结果及照片公共访问失效。
- 个人记录按账号隔离；公开页面只读取有效公开内容。

### 共鸣与音乐

- 按歌手、歌曲、演出或标签搜索听友公开记录，点击卡片进入完整故事和相册。
- “AI 经历匹配”使用本地 E5 检索相近经历，返回作者公开原文供用户判断；模型缺失、忙碌或失败时降级为关键词搜索。
- 歌曲页可切换“听友故事 / 我的记忆”，也可直接开始记录。
- 5 首原创器乐样例支持真实播放、进度拖动和片段定位；设置结束位置后，播放到该处停止。
- 已收录真实歌曲可关联记忆并通过链接在 QQ 音乐查看，站内音源尚未接入。

### 演出足迹

- 地图可浏览 47 个省会／主要城市，当前目录包含 7 位歌手／组合、84 条日期记录、16 个场馆，其中 3 条记录标记取消。
- 点具体场次直接进入星空；点地图歌手头像先查看当地场次，再选择那一晚。返回保留原筛选和列表位置。
- 默认展示往期，“接下来”仅展示北京时间今天起七个自然日；支持月份、歌手和日期搜索。
- 同一歌手、巡演、城市和场馆的相邻日期合并为连场，记录和收藏仍绑定具体日期。
- 歌手关注、场次收藏、到场标记和歌单收藏分别保存，可通过“我的歌手”“我的收藏”找回。
- 星空使用对应场馆的虚拟内景，支持歌曲星点、歌单展开／收起，以及“我的记录 / 听友公开记录”。
- 收藏歌单保留当时的曲目和资料版本；目录更新时由用户确认更新，不自动覆盖收藏。

## 快速体验

1. 打开首页，进入“共鸣”浏览公开故事，或通过底部中央“＋”创建记忆。
2. 写下经历、添加照片并选择配乐，按需填写时间地点，选择私密保存或公开发布。
3. 在“我的记忆”找回记录，打开详情查看照片、编辑内容或调整可见范围。
4. 从“我的”切换到“足迹”，点场次进入星空，查看曲目或记录这一晚。
5. 在“共鸣”按歌曲、标签或一句经历查找听友公开记录。

可以注册个人账号，也可以使用小林、阿远两个共享样例账号。样例包含私密和公开记录，其中 6 条演出记录带有 2–3 张照片。

**共享账号内的操作会被所有体验者看到，请只填写虚构内容；真实记录请使用个人账号。样例故事为虚构内容，生成场景不代表对应演出的实拍。**

## 本地启动

### 环境要求

- Python 3.12。
- Node.js 22.12 或更高版本。
- pnpm，推荐使用已提交的锁文件安装依赖。

基础体验不需要 GPU、模型文件或 QQ 音乐密钥。先确认 `python --version` 和 `node --version` 正常。

以下为 Windows PowerShell 命令。开发中的最新修改先推送到 **lxy**，再由作者合并到 main；新协作者可浅克隆最新开发分支：

```powershell
git clone --branch lxy --single-branch --depth 1 https://github.com/Saskia-1/TME.git
cd TME
```

### 启动后端

在仓库根目录打开终端：

```powershell
cd backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### 启动前端

另开终端，从仓库根目录开始：

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1
```

没有 pnpm 时先运行 `npm install -g pnpm@11.19.0`。也可使用 `npm install` 和 `npm run dev -- --host 127.0.0.1`，但 npm 不读取 pnpm 锁文件，依赖版本可能不同。

两个终端都保持运行，打开 **http://localhost:5173**。前端将 `/api` 代理到本机 8000 端口后端，同源访问保留会话 Cookie；会话有效期为 24 小时。

SQLite 数据库位于 `backend/data/demo.db`，启动时增量补齐旧表字段，不重置已有内容。请保留该目录。macOS／Linux 使用 `python3` 创建环境，Python 和 Hugging Face 命令分别改用 `.venv/bin/python`、`.venv/bin/hf`。

开发服务与构建预览固定使用 5173，端口占用时会报错。体验构建版时先停止开发服务，再在 `frontend` 执行：

```powershell
pnpm build
pnpm preview --host 127.0.0.1
```

### 启用经历匹配（可选）

先确认基础版正常运行，再在 `backend` 目录安装额外依赖并下载模型：

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-ai.txt
.venv/Scripts/hf.exe download Xenova/multilingual-e5-small onnx/model_quantized.onnx tokenizer.json sentencepiece.bpe.model config.json tokenizer_config.json --revision 761b726dd34fb83930e26aab4e9ac3899aa1fa78 --local-dir models/multilingual-e5-small
```

模型文件不提交到 Git。下载完成后重启后端，访问 `http://127.0.0.1:8000/api/search/status` 查看是否就绪。模型的 [ONNX 版本](https://huggingface.co/Xenova/multilingual-e5-small) 源自 [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small)。

推理在应用后端运行，查询和记录不发送给模型服务商。公共经历匹配只使用有效公开内容，不读取私人正文或补记；最多返回 3 条候选，返回前再次检查发布状态和版本。语义检索有 5 秒等待上限，同一时间运行一个模型任务，超时或不可用时降级为关键词。

当前每次请求重新编码候选，尚无向量索引或正文缓存。相似度阈值 0.865 是初始参数，不代表置信度；匹配仍可能遗漏或混淆场景，尚未完成系统评测和真实用户对照。

## 常见问题

| 问题 | 检查与处理 |
| --- | --- |
| 克隆或拉取慢 | 先区分网络连接和对象下载。首次克隆可使用 `--depth 1`，旧 Git 历史仍包含较大的图片资源。 |
| 安装依赖卡住 | 基础版只安装 `requirements.txt`，无需先下载模型；检查 Python／Node 版本及终端最后几行错误。 |
| 页面一直加载 | 确认两个服务都在运行；访问 `http://127.0.0.1:8000/api/songs` 应返回歌曲 JSON。 |
| 保存或上传超时 | 读取请求最长等待 12 秒，保存／上传最长 30 秒。超时不代表服务端未写入，先查看最新状态再重试。 |
| 足迹底图慢或不显示 | 地图瓦片来自外部服务，需要网络；场次列表和本地星空资源不依赖瓦片就绪。三维场景需要 WebGL 2，不支持时仍可使用日程和歌单。 |
| 图片不显示 | 在浏览器 Network 检查具体请求是否 404。项目图片、字体、样例照片和原创音频随代码提交；个人上传照片在本地数据库内，不会随 Git 共享。 |
| 草稿找不到 | 使用保存时的浏览器、账号和地址。`localhost`、`127.0.0.1` 及不同端口的存储范围不同；换设备或清除站点数据后无法从服务器找回。 |
| AI 匹配不可用 | 查看 `/api/search/status`，确认可选依赖和模型文件齐全；没有模型仍可使用关键词搜索和其他基础功能。 |

## 当前限制

- **音乐接入**：尚未接入 QQ 音乐全曲库、歌词、平台账号和站内播放器。真实歌曲的站内音源暂缺，不用原创样例替代歌手录音。支持为曲目提供可播放的 `audio_url`，QQ 音乐搜索网页不能作为音频地址。
- **现场资料**：目录是截至 2026-10-01 核对的部分场次，不是全国实时日程。当前曲目主要为歌手关联作品，尚未确认完整现场歌单；场次收藏与歌单只保存在项目账号内，不同步 QQ 音乐账号。
- **场馆画面**：星空为虚拟场景示意，不是现场实拍或场馆测绘；地图坐标不代表出入口导航终点。360° 环绕功能已停用。
- **草稿存储**：草稿仅保存在当前浏览器，尚未同步云端。不同标签页同时修改时保留独立版本，正常新建和退出登录不会主动删除已有草稿。
- **照片存储**：支持 JPEG、PNG、WebP，单张不超过 5 MiB。上传后校验、移除元数据并缩放至最长边不超过 2048px 的 JPEG，存入数据库；删除记忆尚不会自动回收未引用照片。
- **上线与验证**：账号独立于 QQ 音乐，尚无密码找回。前端、后端、E5 和数据库部署在腾讯云香港服务器，通过 GitHub 检查后自动更新，服务地址、验收记录和恢复方法见[部署说明](docs/DEPLOY.md)。原数据库保留迁移备份，尚未配置定时异地备份；真实用户回访与平台接入效果尚未验证。

## 项目结构

```text
frontend/               前端应用
  src/                  页面、组件与交互
  public/               图片、字体等静态资源
backend/                后端服务
  app/                  API、数据与检索逻辑
  app/sample_photos/    样例照片
  media/                原创演示音频
  models/               可选模型，本地下载
  data/                 本地数据库，不随 Git 共享
docs/                   日程维护与项目资料
```

日程新增、改期、取消和歌单变更可使用本地维护工具预览、核对后更新；目前未启用自动采集。操作方法见[资料维护说明](docs/footprints-data-maintenance.md)。地图和照片的来源、许可保留在地图信息面板及资源元数据中，原创音频信息见[音频说明](backend/media/README.md)。
